Pattern matching & records — blank-page drills

18 drills covering what makes 2025 C# look different from 2015 C#. Switch expressions, property patterns, records, value objects, and the “with” expression. Same rules: no AI, learn.microsoft.com only, 10-min timer.

Why this matters

If you can recognise where to replace an if/else ladder with a switch expression, or a class with a record, or a builder with a with expression — you write code that looks like it was written in this decade. That's a real signal in code review, and more importantly, the resulting code is shorter, safer, and easier to reason about.

Two big wins to aim for:

  • Pattern matching turns “type-check then cast” into one step, and replaces big switch statements with expressions that return a value.
  • Records give you value equality, deconstruction, immutability, and the with expression — all for free. They turn 50-line DTO classes into one-liners.

1 — Switch expressions

Drill 1 — HttpStatusMessage

5 minswitch expression
Goal

Given an HTTP status code (int), return a short message. Use a switch expression, not switch statement or if/else.

Signature
public static string StatusMessage(int code)
Examples
StatusMessage(200)  // "OK"
StatusMessage(404)  // "Not Found"
StatusMessage(500)  // "Server Error"
StatusMessage(418)  // "I'm a teapot"
StatusMessage(999)  // "Unknown"
Self-check
  • The whole method is an expression-bodied member (=>).
  • I have a discard pattern (_) for the “unknown” case.
  • I know what the compiler does if my switch is non-exhaustive without the discard. (Hint: warning.)
Hint

Shape: public static string StatusMessage(int code) => code switch { 200 => "OK", 404 => "Not Found", _ => "Unknown" };. The _ is the catch-all.

Drill 4 — TupleSwitch

8 mintuple patterns
Goal

Write a rock-paper-scissors judge. Take two strings ("rock", "paper", or "scissors") and return "player1", "player2", or "draw". Use a switch expression on a tuple.

Signature
public static string Judge(string p1, string p2)
Self-check
  • I switched on (p1, p2), not nested if/elses.
  • I handled the draws with a single “same-same” arm using a variable pattern: (var a, var b) when a == b => "draw". Or used three explicit arms.
  • I have a discard for invalid inputs.
Hint 
(p1, p2) switch
{
    ("rock",     "scissors") => "player1",
    ("paper",    "rock")     => "player1",
    ("scissors", "paper")    => "player1",
    // ... the symmetric cases for player2
    (var a, var b) when a == b => "draw",
    _ => "invalid"
};

Drill 6 — ShippingCost

10 minswitch + property patterns
Goal

Given an Order(decimal Total, bool IsExpress, string Country), return a shipping cost using a switch expression with property patterns:

  • If Total >= 100 and not express: free.
  • If express: 15.
  • If country is “PT”: 5.
  • Else: 10.
Signature
public static decimal ShippingCost(Order order)
Self-check
  • I switched on order directly with property patterns, not on a tuple of its fields.
  • The order of arms matters — I put more-specific arms first.
  • I can articulate why “express AND total >= 100” should be tested before plain “total >= 100”.
Hint 
order switch
{
    { Total: >= 100, IsExpress: false } => 0,
    { IsExpress: true }                  => 15,
    { Country: "PT" }                     => 5,
    _                                    => 10
};

Why order matters: switch arms are tried top-down, first match wins. An express order with total 200 should pay 15 (express trumps free shipping by your rules) — or should it? Decide the business rule first; the order of arms follows.

3 — Type patterns & "is"

5 minis + variable

Signature
public static int DoubleIfInt(object? value)
Self-check

Drill 9 — DescribeShape

10 mintype patterns in switch
Goal

Given a base abstract record Shape, with derived types Circle(double Radius), Rectangle(double Width, double Height), and Triangle(double Base, double Height), return the area. Use a switch expression with type patterns and deconstruction.

Signature
public static double Area(Shape shape)
Self-check
  • I used positional patterns (deconstruction): Circle(var r) => ....
  • The switch is exhaustive — no warning from the compiler. (Or there is, and I added a discard.)
  • I know that records get Deconstruct automatically, which is what makes positional patterns work.
Hint 
shape switch
{
    Circle(var r)        => Math.PI * r * r,
    Rectangle(var w, var h) => w * h,
    Triangle(var b, var h)  => 0.5 * b * h,
    _                       => throw new ArgumentException("unknown shape")
};

This pattern — sealed/abstract base + discriminated derived types + exhaustive switch — is C#'s closest thing to a sum type. Sealed the base if you want the compiler to enforce exhaustiveness (in modern .NET).

Drill 10 — NotNull (no code — explain)

5 minis not null
Goal

Compare these three guard styles:

if (value != null) { ... }
if (value is not null) { ... }
if (value is { }) { ... }

All three look equivalent. Are they? Write 2–4 sentences explaining when they differ.

Hint

!= can be overloaded — some types lie about equality. is not null can't be overloaded — it asks the runtime, not the type. That's why FxCop / analyzers nudge you toward is not null. is { } is equivalent to is not null for reference types; the empty property pattern just means “an object exists, no further requirements”.

Drill 14 — WithExpression

5 minwith
Goal

Take the Person from Drill 13. Create one instance, then use the with expression to make a new instance with only the Age changed.

var ana   = new Person("Ana", "Silva", 30);
var older = ana with { Age = 31 };

// older.Age == 31, ana.Age still == 30, both are independent objects
Self-check
  • The original instance is unchanged. with creates a new one.
  • I know with only works on records (and structs marked record). It does not work on regular classes.
  • I can name two scenarios where with is the right tool. (Hint: settings, immutable state, “edited copies”.)

Drill 15 — Email value object

12 minrecords as value objects
Goal

Make an Email record that wraps a single string. The constructor must reject invalid emails (anything without an @ and a dot for this drill — don't over-engineer the validation). Once constructed, the value cannot be changed.

Behaviour
var ok  = new Email("ana@example.com");   // fine
var bad = new Email("not-an-email");      // throws ArgumentException

var a = new Email("x@y.com");
var b = new Email("x@y.com");
a == b;  // true (value equality)
Self-check
  • I used a positional record but with validation in the body.
  • I can articulate what a “value object” is and why Email qualifies. (Hint: domain meaning, equality by value, immutable, can't exist in invalid state.)
  • I have a test for the throws case.
Hint 
public sealed record Email(string Value)
{
    public Email(string Value) : this()  // ... no, that's wrong
}

Hmm. Positional records' validation is done in the primary constructor body, which is the part after the parameter list. The idiomatic shape:

public sealed record Email
{
    public string Value { get; }

    public Email(string value)
    {
        if (!value.Contains('@') || !value.Contains('.'))
            throw new ArgumentException("invalid email", nameof(value));
        Value = value;
    }
}

Or if you prefer the positional shape, use a static factory Email.Create(...) that validates and a private constructor.

Drill 16 — Record vs class (no code — explain)

10 mindesign
Goal

You're designing two types: User (someone who logs in, has an Id, can change their display name) and Money (an amount + currency, used for prices and totals). For each:

  1. Class or record? Why?
  2. If record: sealed?
  3. If class: which override(s) would you add?
Hint — my answer

User: class. A user has an identity (the Id). Two users with different display names but the same Id are the same user, not equal-by-value. Records would make two users with the same name equal — wrong. Override Equals and GetHashCode to compare by Id only.

Money: sealed record. 5.00 EUR is fungible with any other 5.00 EUR — pure value semantics. Use with if you need “same amount, different currency” (though that's actually a different domain operation; with would just lie about it — a method ConvertTo(currency, rate) is more honest).

The principle: does identity matter, or only the values? Identity matters → class. Only values → record.

6 — Design: when to use what

Drill 17 — Refactor an if-ladder (no fresh code — rewrite)

10 minrefactor
Goal

Take this old-style code. Rewrite it as a switch expression using pattern matching. The new version should be one expression.

public string Describe(object? value)
{
    if (value == null) return "null";
    if (value is int) {
        var i = (int)value;
        if (i == 0) return "zero";
        if (i > 0) return "positive int";
        return "negative int";
    }
    if (value is string s && s.Length == 0) return "empty string";
    if (value is string) return "non-empty string";
    return "something else";
}
Self-check
  • The new version is a single switch expression.
  • I used a property pattern on string to test for empty: string { Length: 0 }.
  • Both versions return the same string for every input I tested.

Drill 18 — When NOT to use pattern matching (no code)

5 minjudgment
Goal

Pattern matching is a hammer — everything starts to look like a nail. In 3–5 sentences, name two situations where a plain method call, polymorphism, or a dictionary lookup is genuinely better than a switch expression.

Hint

(1) If you find yourself adding a new arm to the same switch every time a new shape is added, the switch is a substitute for polymorphism — consider making the operation a virtual method on the base type instead. The switch leaks the type hierarchy across the codebase. (2) If the mapping is purely data (status code → string with 50+ entries), a Dictionary<int, string> initialised once is cheaper and easier to maintain than a 50-arm switch expression.
