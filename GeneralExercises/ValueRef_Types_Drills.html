Value vs reference types — blank-page drills

15 drills covering the most foundational mental model in .NET: where things live (stack vs heap), what gets copied when, struct vs class, and modern nullable reference types. Companion: _Organized/01-Basics/CSharp_Stack_and_Heap_Guide.html.

Why this

If you don't know whether a = b copies the value or shares a reference, you can't reason about bugs reliably. This is the most-skipped topic in C# courses because it “feels theoretical” — until you're staring at a bug where mutating one object accidentally mutated another.

Read _Organized/01-Basics/CSharp_Stack_and_Heap_Guide.html before starting. The drills test what the guide explains.

1 — What gets copied

Drill 1 — Int assignment

5 minvalue type copy
Goal

Predict, then run:

int a = 5;
int b = a;
b = 10;
Console.WriteLine(a);
Console.WriteLine(b);

Now do the same with List<int>:

var x = new List<int> { 1, 2, 3 };
var y = x;
y.Add(4);
Console.WriteLine(x.Count);
Console.WriteLine(y.Count);
Self-check
  • I predicted both before running.
  • I can articulate: int is a value type — assignment copies the value. List is a reference type — assignment copies the reference to the same object.
  • Both x.Count and y.Count are 4 in the second case.

Drill 2 — Pass by value (predict)

8 minparameter passing
Goal

Predict each:

static void SetInt(int n)    { n = 99; }
static void AddTo(List<int> list) { list.Add(99); }
static void ReplaceList(List<int> list) { list = new() { 99 }; }

int a = 5;            SetInt(a);       Console.WriteLine(a);
var b = new List<int> { 1 };  AddTo(b);        Console.WriteLine(b.Count);
var c = new List<int> { 1 };  ReplaceList(c);  Console.WriteLine(c.Count);
Self-check
  • I got all three right.
  • I can explain why AddTo changes the caller's list (mutating the object the reference points to) but ReplaceList doesn't (reassigning the local reference variable, which is a copy).

Drill 3 — ref parameters

5 minref / out
Goal

Rewrite SetInt from Drill 2 with ref. Now it changes the caller's variable. Do the same for ReplaceList — now reassignment does reach the caller.

Self-check
  • I know ref means “pass the variable, not its value” — even for reference types.
  • I know out is like ref but caller doesn't need to initialise the variable first.
  • I can name a real-world reason for ref: TryParse's out result, Interlocked.Exchange, struct mutation helpers.

Drill 4 — Shared reference bug

8 minaliasing bug
Goal

Write a class Settings with a List<string> AllowedHosts property. Create two instances:

var defaults = new Settings { AllowedHosts = new() { "localhost" } };
var prod     = new Settings { AllowedHosts = defaults.AllowedHosts };

prod.AllowedHosts.Add("prod.example.com");

Console.WriteLine(string.Join(", ", defaults.AllowedHosts));

Predict, then run, then fix.

Self-check
  • defaults.AllowedHosts now contains prod.example.com too — not what you wanted.
  • I fixed it by copying the list: AllowedHosts = new List<string>(defaults.AllowedHosts).
  • I now know to be paranoid about shared references in “duplicating” or “copying” code.

2 — struct vs class

Drill 5 — PointStruct

8 minstruct basics
Goal

Declare PointStruct as a struct with int X, Y. Then:

var a = new PointStruct { X = 1, Y = 2 };
var b = a;
b.X = 99;

Console.WriteLine(a.X);  // ?
Console.WriteLine(b.X);  // ?
Self-check
  • I predicted: a.X == 1, b.X == 99.
  • I know structs are value types — assignment copies the whole struct.

Drill 6 — Mutating struct trap (predict)

10 minstruct in collection
Goal

Predict:

var points = new List<PointStruct> { new() { X = 1, Y = 2 } };
points[0].X = 99;
Console.WriteLine(points[0].X);

Try to compile. Then read the error. What does it tell you about structs in collections?

Hint

Compile error: “Cannot modify the return value of 'List<PointStruct>.this[int]' because it is not a variable”. The indexer returns a copy of the struct — mutating the copy would be pointless. The compiler prevents you from doing it accidentally.

To “modify” an element: points[0] = points[0] with { X = 99 }; — replace the whole entry. Or use a class. This is the canonical “why structs are dangerous if mutable” lesson.

Drill 7 — readonly struct

5 minreadonly struct
Goal

Rewrite PointStruct as readonly struct. Make X and Y init-only. Verify you can't accidentally mutate the struct.

Self-check
  • The struct compiles with readonly struct.
  • Once constructed, X and Y cannot change — the compiler enforces it.
  • I know the rule: structs should be immutable unless you have a very specific perf reason.

Drill 8 — record struct

5 minrecord struct
Goal

Rewrite PointStruct one more time as public readonly record struct PointStruct(int X, int Y);. Confirm it works the same and now you get value equality for free.

Self-check
  • The whole declaration is one line.
  • new PointStruct(1, 2) == new PointStruct(1, 2) is true.
  • I now know the modern way to write “small immutable value type with value equality”.

Drill 9 — When struct, when class? (no code)

10 minjudgment
Goal

For each, pick struct or class:

  1. A 2D point with X and Y coordinates.
  2. An entity representing a user.
  3. A date range (Start, End).
  4. A configuration object with 20 fields.
  5. An RGB colour.
Hint — my picks
  1. Struct (record struct) — small, value semantics, immutable.
  2. Class — identity matters (the user has an Id), it may grow fields, value semantics aren't right.
  3. Struct (record struct) — two DateOnly fields, value semantics.
  4. Class — large; structs over ~16–24 bytes start to hurt due to copying. Also, this likely needs to flow through APIs unchanged.
  5. Struct — 4 bytes, value semantics, immutable.

Rule of thumb from Microsoft: structs should be small (~16 bytes), immutable, and represent a single value (a point, a money, a colour, a duration). Default to class otherwise.

3 — Nullable reference types

Drill 10 — Nullable annotations

5 min? annotation
Goal

Write two method signatures:

public string GetName();      // never returns null
public string? FindEmail();    // may return null

Now write a third that takes a nullable param:

public void LogMaybe(string? message);

For each, write 2 lines of caller code: one that respects the nullability, one that violates it. Observe the compiler warnings.

Self-check
  • I confirmed the project has <Nullable>enable</Nullable> in the csproj.
  • I get a warning when I deref a nullable without checking.
  • I know the annotation is documentation — the compiler enforces it but it doesn't change runtime behaviour.

Drill 11 — The null-forgiving operator

5 min! operator
Goal

Find a place to use the null-forgiving operator (!) legitimately. Example:

var dict = new Dictionary<string, string> { ["a"] = "alpha" };
if (dict.TryGetValue("a", out var value))
{
    // here, value is non-null, but the compiler can't always prove it
    Console.WriteLine(value!.Length);
}
Self-check
  • I used ! only when I knew more than the compiler.
  • I considered: every ! is a place that could throw at runtime. Treat each like a load-bearing assumption.
  • I know the lazy use of ! — sprinkling it to silence warnings — defeats the entire nullable system.

Drill 12 — The default(T) trap

8 mindefault for generic T
Goal

Write a generic method that returns default(T) for any T. Call it with int, DateTime, string, List<int>. Predict each result.

Hint

int → 0. DateTime → DateTime.MinValue. string → null. List<int> → null. The trap: default(string) is null even though string is a reference type — the compiler accepts it without a warning inside a generic method, but the value is null. If the caller assumed non-null T, you've planted a null reference.

Drill 13 — Defensive against null at boundary

5 minArgumentNullException.ThrowIfNull
Goal

Write a public service method that takes a string name parameter. Use the modern guard:

ArgumentException.ThrowIfNullOrWhiteSpace(name);

Confirm what it throws for null vs empty vs whitespace.

Self-check
  • I know ArgumentException.ThrowIfNullOrWhiteSpace is the modern one-liner (since .NET 8).
  • I prefer it over the manual if (...) throw ... pattern.
  • I use these guards at public boundaries only, not in every private helper (see Exception drills #15).

4 — Design

Drill 14 — The boxing cost

10 minboxing
Goal

Write a loop that adds 1,000,000 ints to a List<object>. Time it.

Write a loop that adds 1,000,000 ints to a List<int>. Time it.

Compare. Explain the difference using the word “box”.

Hint

List<object> stores each int as a boxed object on the heap — allocation per element. List<int> stores them packed in an array of int. The first is slower, allocates more, and pressures the GC. This is the original motivation for generics in .NET 2.0 — pre-generics collections were all object-based.

Drill 15 — Reading a method signature (no code)

10 minsignature literacy
Goal

For each signature, answer:

  1. Is the return type a value or reference type? How do you know?
  2. Is the input passed by value or by reference?
  3. Can the input be null?
  4. Can the return be null?
public User? Find(int id);
public decimal CalculateTotal(Order order);
public void Update(ref int value);
public IReadOnlyList<string> Tokenize(string? input);
public bool TryParse(string input, out DateTime result);

If you can answer those four questions for every signature you encounter, you're reading C# fluently.

After these

You can now answer the question every senior dev expects you to: “when you do a = b, what really happens?” That's the bedrock of debugging memory bugs and writing predictable code.
