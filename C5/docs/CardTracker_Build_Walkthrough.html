CardTracker — build walkthrough (our variant)

A complete, do-it-from-scratch recipe for the Chapter 5 Web API the way we built it — which diverges from the book enough that neither the book nor the answer key will guide you here. Follow top to bottom and you'll have a building, runnable API.
Living document. Covers everything through the card CRUD endpoints (book ~p.160). The JWT auth section (Services / Settings / Login-User-Deck endpoints) is sketched at the end and will be filled in as we build it.

1 — Bootstrap the project

From your chapter folder (C5/):

# solution + project inside a CardTracker wrapper folder
# (the wrapper matters: Ch.6 adds Contracts + Client projects beside the API)
mkdir CardTracker && cd CardTracker
dotnet new sln -n CardTracker          # use .slnx to match your other chapters
dotnet new web -n CardTrackerWebApi
dotnet sln add CardTrackerWebApi
cd CardTrackerWebApi

Add packages (note: Mapperly, not AutoMapper):

dotnet add package Microsoft.EntityFrameworkCore.Sqlite          -v 10.0.0
dotnet add package Microsoft.EntityFrameworkCore.Design          -v 10.0.0
dotnet add package Microsoft.EntityFrameworkCore.Tools           -v 10.0.0
dotnet add package Microsoft.AspNetCore.OpenApi                  -v 10.0.0
dotnet add package Microsoft.AspNetCore.Authentication.JwtBearer -v 10.0.0   # for the auth phase
dotnet add package Riok.Mapperly                                              # NOT AutoMapper
dotnet tool install --global dotnet-ef                                        # once per machine
Divergence: the book installs AutoMapper here. We don't — Mapperly replaces it. If AutoMapper crept into your csproj, remove it (dotnet remove package AutoMapper); it also clears the NU1903 vulnerability.

appsettings.json — add the connection string

"ConnectionStrings": {
  "DefaultConnection": "Data Source=cardtracker.db"
}

GlobalUsings.cs — real global usings (this file must contain directives, not a class)

global using Microsoft.EntityFrameworkCore;
global using System.ComponentModel.DataAnnotations;
global using System.ComponentModel.DataAnnotations.Schema;
global using CardTrackerWebApi.Models;
global using CardTrackerWebApi.Models.Configuration;
global using CardTrackerWebApi.Requests;
global using CardTrackerWebApi.Responses;
global using CardTrackerWebApi.Mappings;
global using CardTrackerWebApi.Endpoints;
The recurring trap: a file named GlobalUsings.cs is not special — it must hold global using lines, not public class GlobalUsings { }. With the block above, the per-file usings shown later become optional.

2 — The data model

Models/BaseEntity.cs

public abstract class BaseEntity
{
    [Key, DatabaseGenerated(DatabaseGeneratedOption.Identity)]
    public int Id { get; set; }
}
Divergence: one Id for every entity instead of repeating [Key] int Id in each class.

Models/User.cs

[Index(nameof(Username), IsUnique = true)]
public class User : BaseEntity
{
    public required string Username { get; set; }
    public required byte[] PasswordHash { get; set; }
    public required byte[] Salt { get; set; }
    public bool IsAdmin { get; set; }
}

Models/Card.cs, ActionCard.cs, CreatureCard.cs

public abstract class Card : BaseEntity
{
    public required string Name { get; set; }
    public string? Description { get; set; }
    public string? ImagePath { get; set; }
    public List<Deck> Decks { get; set; } = [];   // inverse nav (EF only)
}

public class ActionCard : Card
{
    public required string Effect { get; set; }
    public required int Cost { get; set; }
}

public class CreatureCard : Card
{
    public string? SummonEffect { get; set; }
    public string? PerTurnEffect { get; set; }
    public required int SummonCost { get; set; }
    public required int Power { get; set; }
    public bool CanFly { get; set; }
    public bool CanSwin { get; set; }
    public bool CanClimb { get; set; }
}

Models/Deck.cs & Models/CardDeck.cs

public class Deck : BaseEntity
{
    public required string Name { get; set; }
    public required int UserId { get; set; }
    public List<CardDeck> CardDecks { get; set; } = [];
}

[PrimaryKey(nameof(CardId), nameof(DeckId))]   // composite key
public class CardDeck
{
    public required int CardId { get; set; }
    public required int DeckId { get; set; }
    public int Count { get; set; } = 1;   // join payload: copies per deck
}

3 — EF configuration & DbContext

Divergence: the book puts all this inline in OnModelCreating. We split it into IEntityTypeConfiguration<T> classes (under Models/Configuration/) and apply them in one line. Remember: a config class only runs if you apply it.

Models/Configuration/CardConfiguration.cs — the inheritance strategy

public class CardConfiguration : IEntityTypeConfiguration<Card>
{
    public void Configure(EntityTypeBuilder<Card> builder)
    {
        builder.UseTptMappingStrategy();   // Table-Per-Type
    }
}

TPT = one table per type: a Cards table (base columns) plus ActionCards and CreatureCards tables (subtype columns + an FK to Cards). Queries join them. (Alternatives: TPH one table + discriminator column, fastest; TPC one table per concrete type, no base table. The book tries all three; we settled on TPT.)

Models/Configuration/DeckConfiguration.cs — the relationships

public class DeckConfiguration : IEntityTypeConfiguration<Deck>
{
    public void Configure(EntityTypeBuilder<Deck> builder)
    {
        builder.HasOne<User>()                // each Deck has one owner User
            .WithMany()
            .HasForeignKey(d => d.UserId);

        builder.HasMany<Card>()                // Deck ↔ Card many-to-many...
            .WithMany(c => c.Decks)
            .UsingEntity<CardDeck>();         // ...through the CardDeck join (carries Count)
    }
}
Watch the cardinality: the second block must be HasMany (many-to-many) — UsingEntity only exists on the many-to-many builder. HasOne there won't compile.

Models/CardsDbContext.cs

public class CardsDbContext(DbContextOptions<CardsDbContext> options)
    : DbContext(options)
{
    public DbSet<User> Users { get; set; }
    public DbSet<Deck> Decks { get; set; }
    public DbSet<Card> Cards { get; set; }
    public DbSet<ActionCard> ActionCards { get; set; }
    public DbSet<CreatureCard> CreatureCards { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
        => modelBuilder.ApplyConfigurationsFromAssembly(typeof(CardsDbContext).Assembly);
}

4 — Migrations

The book punts on migrations. You run them yourself, from CardTrackerWebApi/:

dotnet ef migrations add Initial
dotnet ef database update          # creates cardtracker.db

With TPT you'll see separate Cards, ActionCards, CreatureCards tables, a CardDeck table with a composite PK, and the unique index on User.Username. Re-run both commands after every model change.

5 — DTOs (Responses & Requests)

Responses/ — required + a read-only Type discriminator, no secrets

public abstract class CardResponse
{
    public int Id { get; init; }
    public required string Name { get; init; }
    public string? Description { get; init; }
    public string? ImagePath { get; init; }
    public abstract string Type { get; }      // emitted so clients can tell subtypes apart
}
public class ActionCardResponse : CardResponse
{
    public override string Type => "Action";
    public required string Effect { get; init; }
    public required int Cost { get; init; }
}
public class CreatureCardResponse : CardResponse
{
    public override string Type => "Creature";
    public string? SummonEffect { get; init; }
    public string? PerTurnEffect { get; init; }
    public required int SummonCost { get; init; }
    public required int Power { get; init; }
    public bool CanFly { get; init; }
    public bool CanSwin { get; init; }
    public bool CanClimb { get; init; }
}

public class UserResponse
{
    public int Id { get; init; }
    public required string Username { get; init; }
    public bool IsAdmin { get; init; }
    // deliberately NO PasswordHash / Salt
}

Requests/CreateCardRequest.cs — polymorphic input via built-in System.Text.Json

using System.Text.Json.Serialization;
namespace CardTrackerWebApi.Requests;

[JsonPolymorphic(TypeDiscriminatorPropertyName = "type")]
[JsonDerivedType(typeof(CreateActionCardRequest),   "Action")]
[JsonDerivedType(typeof(CreateCreatureCardRequest), "Creature")]
public abstract class CreateCardRequest
{
    public required string Name { get; init; }
    public string? Description { get; init; }
    public string? ImagePath { get; init; }
}
public class CreateActionCardRequest : CreateCardRequest
{
    public required string Effect { get; init; }
    public required int Cost { get; init; }
}
public class CreateCreatureCardRequest : CreateCardRequest
{
    public string? SummonEffect { get; init; }
    public string? PerTurnEffect { get; init; }
    public required int SummonCost { get; init; }
    public required int Power { get; init; }
    public bool CanFly { get; init; }
    public bool CanSwin { get; init; }
    public bool CanClimb { get; init; }
}
Divergence: the book writes a custom JsonConverter (CreateCardRequestConverter) to pick the subtype. We use the built-in [JsonPolymorphic]/[JsonDerivedType] attributes instead — zero custom code. The trade-off: STJ requires "type" to be the first property in the body. If you need order-independence, that's when the custom converter earns its keep.

6 — Mapping with Mapperly

Mappings/CardMapper.cs

using Riok.Mapperly.Abstractions;
namespace CardTrackerWebApi.Mappings;

[Mapper]
public partial class CardMapper
{
    // entity -> response (polymorphic out)
    [MapperIgnoreSource(nameof(Card.Decks))]
    [MapDerivedType<ActionCard,   ActionCardResponse>]
    [MapDerivedType<CreatureCard, CreatureCardResponse>]
    public partial CardResponse ToResponse(Card card);

    // collection: NO attributes - reuses ToResponse(Card) per element
    public partial List<CardResponse> ToResponse(IEnumerable<Card> cards);

    // request -> entity (polymorphic in)
    [MapperIgnoreTarget(nameof(Card.Id))]      // DB-generated, never from client
    [MapperIgnoreTarget(nameof(Card.Decks))]
    [MapDerivedType<CreateActionCardRequest,   ActionCard>]
    [MapDerivedType<CreateCreatureCardRequest, CreatureCard>]
    public partial Card ToEntity(CreateCardRequest request);
}

Mappings/UserMapper.cs

[Mapper]
public partial class UserMapper
{
    [MapperIgnoreSource(nameof(User.PasswordHash))]
    [MapperIgnoreSource(nameof(User.Salt))]
    public partial UserResponse ToResponse(User user);
}

Key rules learned the hard way: [MapDerivedType] is for the single-item polymorphic method only (lists reuse it per element); MapperIgnoreSource documents intentionally-dropped entity data; MapperIgnoreTarget handles DB-managed fields like Id.

7 — Endpoints (REPR)

One static class per resource; each handler is a small static method. The polymorphic create is the showpiece — the discriminator drives the whole chain.

Endpoints/CardEndpoints.cs

namespace CardTrackerWebApi.Endpoints;

public static class CardEndpoints
{
    public static void AddCardEndpoints(this WebApplication app)
    {
        app.MapGet("cards", HandleGetAllCards).AllowAnonymous();
        app.MapGet("cards/{id}", HandleGetCardById).AllowAnonymous();
        app.MapPost("cards", HandleCreateCard).RequireAuthorization("AdminOnly");
        app.MapDelete("cards/{id}", HandleDeleteCard).RequireAuthorization("AdminOnly");
    }

    private static async Task<IResult> HandleGetAllCards(CardsDbContext db, CardMapper mapper)
    {
        List<Card> cards = await db.Cards.AsNoTracking().ToListAsync();
        return Results.Ok(mapper.ToResponse(cards));
    }

    private static async Task<IResult> HandleGetCardById(int id, CardsDbContext db, CardMapper mapper)
    {
        Card? card = await db.Cards.AsNoTracking().FirstOrDefaultAsync(c => c.Id == id);
        return card is null ? Results.NotFound() : Results.Ok(mapper.ToResponse(card));
    }

    private static async Task<IResult> HandleCreateCard(
        CreateCardRequest request, CardsDbContext db, CardMapper mapper)
    {
        Card card = mapper.ToEntity(request);   // request subtype -> entity subtype
        db.Cards.Add(card);
        await db.SaveChangesAsync();            // DB fills card.Id
        return Results.Created($"/cards/{card.Id}", mapper.ToResponse(card));
    }

    private static async Task<IResult> HandleDeleteCard(int id, CardsDbContext db)
    {
        Card? card = await db.Cards.FindAsync(id);
        if (card is null) return Results.NotFound();
        db.Cards.Remove(card);
        await db.SaveChangesAsync();
        return Results.NoContent();
    }
}
The create chain: JSON "type" → STJ picks the request subclass → ToEntity picks the entity subclass → EF saves → ToResponse picks the response subclass. One discriminator, four polymorphic hops.

8 — Program.cs wiring

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenApi();
builder.Services.AddDbContext<CardsDbContext>(o =>
    o.UseSqlite(builder.Configuration.GetConnectionString("DefaultConnection")));

builder.Services.AddSingleton<CardMapper>();   // Mapperly mappers are stateless
builder.Services.AddSingleton<UserMapper>();

var app = builder.Build();

if (app.Environment.IsDevelopment())
    app.MapOpenApi();

app.UseHttpsRedirection();

app.AddCardEndpoints();
app.MapGet("/tea", () => Results.StatusCode(StatusCodes.Status418ImATeapot));

app.Run();
Build order: only call endpoint groups that exist. RequireAuthorization("AdminOnly") compiles but fails at runtime until the auth phase defines that policy — either finish auth or temporarily drop .RequireAuthorization(...) to exercise the endpoints.

10 — Still to come: authentication

Not built yet — this is the next stretch (book ~p.171+). When we get there it adds:

  • Settings/AuthSettings.cs + an appsettings section (JWT key, issuer, audience).
  • Services/ — IHashingService/HmacHashingService (salt + hash passwords) and ITokenGenerationService/JwtGenerationService (issue JWTs).
  • Endpoints/ — LoginEndpoints (issue a token), UserEndpoints, DeckEndpoints, with their Requests/Responses.
  • Program.cs — AddAuthentication().AddJwtBearer(...), AddAuthorization() with the "AdminOnly" policy, and app.UseAuthentication()/UseAuthorization().

Once those exist, the .RequireAuthorization("AdminOnly") on create/delete starts working, and the .http login-then-reuse-token trick ({{login.response.body.$.token}}) lets you hit the protected endpoints.

That's the whole project, our way. Companion docs: mapping approaches, Mapperly guide, book gaps.
